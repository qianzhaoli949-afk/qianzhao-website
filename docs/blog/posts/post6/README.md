# Post 6 — Matching Parents and Children with SQL in Python

This post uses public-use PSID extracts to link birth mothers to adult children and compare intergenerational family-income elasticities. The article is a tutorial and descriptive analysis, not a causal or nationally representative mobility estimate. **PSID person-level data are not included in this public repository.**

## Get the PSID extracts

Create two public-use extracts in the [PSID Data Center](https://simba.isr.umich.edu/). Select **ASCII** output with **Stata statements** and download each ZIP with its codebook. The analysis used:

1. **Parent Identification File**, job `366440`: `PID2`, `PID3` (child's stable ID) and `PID4`, `PID5` (birth mother's stable ID). The extract includes 103,725 records.
2. **Cross-Year Individual File**, job `366441`: `ER30001`, `ER30002` (stable ID); `ER33804`, `ER35104` (ages in 2005 and 2023); and the wave-specific variables below. The extract includes 40,637 records.

| Income year | Interview year | Family income | Family interview ID | Sequence | Relation |
| --- | ---: | --- | --- | --- | --- |
| 2000 | 2001 | `ER20456` | `ER33601` | `ER33602` | `ER33603` |
| 2002 | 2003 | `ER24099` | `ER33701` | `ER33702` | `ER33703` |
| 2004 | 2005 | `ER28037` | `ER33801` | `ER33802` | `ER33803` |
| 2018 | 2019 | `ER77448` | `ER34701` | `ER34702` | `ER34703` |
| 2020 | 2021 | `ER81775` | `ER34901` | `ER34902` | `ER34903` |
| 2022 | 2023 | `ER85629` | `ER35101` | `ER35102` | `ER35103` |

These are **family-income** fields, not individual earnings. Each income year precedes the corresponding interview year. See the downloaded PSID codebooks and [PSID documentation](https://psidonline.isr.umich.edu/Guide/documents.aspx) for variable definitions. The CPI file uses annual averages of monthly [CPIAUCNS](https://fred.stlouisfed.org/series/CPIAUCNS); the script expresses every amount in 2022 dollars.

## Reproduce the empirical results

Use Python 3.9 or later. The script uses only the standard library. Keep the ZIP files outside the website repository, then run from the project root in RStudio's **Terminal** or another terminal:

```sh
python3 blog/posts/post6/code/analyze_psid.py \
  --pid-zip /path/to/J366440.zip \
  --income-zip /path/to/J366441.zip
```

Replace those paths with your own locations if needed. The script reads the ZIPs without unpacking them. It writes only `results/psid_estimates.csv` and `results/psid_elasticities.svg`. It does not export personal IDs or matched rows. Rendering the post does **not** rerun the analysis; rerun the script first if the extracts or filters change, then update any numbers in `index.qmd`.

```sh
quarto render blog/posts/post6/index.qmd
quarto render blog/index.qmd
```

The built website appears under `docs/blog/`.

## Sample and interpretation

The SQL links a child to a **birth mother** using both parts of each person's stable ID. It keeps children aged 30–40 in 2023 and mothers aged 35–70 in 2005, with an implied 15–45 year age gap. It also requires a valid family interview ID, sequence 1–20, reference-person/spouse/partner relation code 10/20/22, and positive non-topcoded family income in each selected wave. Each generation needs all three income years. These rules produce 1,467 complete pairs; all five reported slopes use those same pairs.

The script regresses log adult-child family income on log birth-mother family income with an intercept. These are unweighted sample associations. Missing or nonpositive incomes, incomplete panels, family selection, and measurement of different calendar years limit generalization. The comparison cannot separately identify aging from period changes, and it does not observe true permanent income.

The repository also has a clearly separate simulation. To regenerate that *invented* data and its four estimates, run:

```sh
python3 blog/posts/post6/code/make_data.py
python3 blog/posts/post6/code/analyze.py
```

The simulation intentionally weakens the link between early-career income and long-run income, demonstrating how a single young-age observation **can** understate an IGE in that known setup. Its estimates are not PSID estimates and should never be combined with the empirical table.

Do not add the original PSID ZIPs, their unpacked person-level files, or a matched person-level dataset to GitHub. The project's `.gitignore` protects common extract filenames, but keep the originals in a private local folder and review `git status` before committing.
